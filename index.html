SpawnersUnleashed

Silk-touch spawner drops and spawner placement for Paper, written because two separate faults on modern Paper make spawners come out blank and nothing on the market fixes both.

Paper 26.1 Java 25 No dependencies

The compatibility promise

The dropped item is a plain vanilla spawner with the mob in block_entity_data and nothing else. The display name is cosmetic. That is the whole compatibility story: it works with g2shop, EconomyShopGUI, auction houses, hoppers, shulkers, and with this plugin uninstalled.

Plugins that hide the mob in a lore line produce an item no shop can read and no other plugin can place. That single design choice is why their spawners cannot be sold.

The two bugs it fixes

Non-op survival players place blank spawners

A vanilla rule, not a plugin bug.

MOB_SPAWNER is in BlockEntityType.OP_ONLY_CUSTOM_DATA, so BlockItem.updateCustomBlockEntityTag refuses to copy an item's block_entity_data onto the block unless:

player.canUseGameMasterBlocks()                 // op level 2+
  || (player.getAbilities().instabuild          // creative
      && player.hasPermission("minecraft.nbt.place"))

A survival player gets a blank spawner and is told nothing. No permission fixes it, because the bypass also demands creative. A plugin has to write the type server-side, which this one does at MONITOR so the final block state is correct whatever else touched it.

Mining a spawner returns a blank one

Every Bukkit accessor reads the same field, on the wrong object.

getSpawnedType(), getSpawnedEntity() and getCreatureTypeName() all read BaseSpawner.nextSpawnData on the snapshot returned by Block#getState(), and each returns null when it is unset. A plugin that reads the snapshot then calls setSpawnedType(null), whose null branch sets nextSpawnData = new SpawnData() and serialises as SpawnData:{entity:{}} — the blank spawner you end up holding.

The fix is Block#getState(false): a state backed by the live tile entity instead of an NBT round-trip. SpawnersUnleashed tries that first, falls back through every other accessor, and logs which one won.

If every path fails it drops nothing and warns, rather than minting a blank spawner. A silent dud is worse than no item.

Features

  • Silk-touch drops with configurable minimum level, drop chance, and per-mob chance overrides.
  • Placement repair, so survival players get a working spawner.
  • /su admin edits every setting live in game; config.yml is written back immediately, so nothing is lost on restart and there is no apply button to forget.
  • /su give uses the same item builder as the mined drop, so it is a real test of that path rather than a parallel one that can drift.
  • Spawner-farm finder with single-linkage clustering and teleport-to-group.
  • Optional TNT and creeper drops, per-mob mine and place permissions, world allow and deny lists, fully configurable messages.
  • Menus cannot dupe: decoration-only windows behind a guard that refuses clicks, shift-clicks, drags, hotbar swaps, offhand swaps and hopper pulls at lowest priority.

Taking priority over other spawner plugins

Event priority is not enough. CMI hands its spawner straight to the player's inventory, so no listener ordering can suppress it — if its module is on, one block yields two spawners. Its config is the only real switch:

# plugins/CMI/config.yml
Spawners:
  FullDisable: true

The startup guard re-reads that file every boot and on /su reload, checks eleven known spawner plugins by name, and prints every plugin registered on the break and place events — so a future conflict names itself instead of showing up as a duplicate spawner.

Commands

CommandPermissionWhat it does
/su give <mob> [amount] [player]spawnersunleashed.giveGive a working spawner
/su scan [radius|world]spawnersunleashed.scanFind spawner farms nearby
/su tp <#>spawnersunleashed.scanJump to a group from the last scan
/su adminspawnersunleashed.adminLive settings menu
/su reloadspawnersunleashed.adminReload and re-run the conflict check

spawnersunleashed.drop (default true) is what lets a player collect a spawner at all. spawnersunleashed.bypass.chance ignores the drop chance.

The scanner reads loaded chunks only

Reaching unloaded chunks would mean loading or generating them, which lags a live server. A scan therefore describes the world as it currently is in memory. Run it while the area is occupied — which is exactly when a farm is worth looking at.

Requirements

Paper 26.1 or newer. No dependencies, no library downloads, no database. Drop the jar in plugins/ and restart; the config writes itself on first boot.
