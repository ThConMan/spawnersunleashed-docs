THE ITEM

A spawner, and nothing clever

What drops is a plain vanilla spawner with the mob stored in block_entity_data. That is the whole item. The display name on it is decoration and nothing reads it.

That is also the entire compatibility story. It works with g2shop, EconomyShopGUI, auction houses, hoppers and shulkers. It keeps working if you uninstall this plugin tomorrow.

Plugins that hide the mob in a lore line produce an item no shop can read and no other plugin can place. That one decision is why their spawners cannot be sold.

WHAT ACTUALLY DROPS minecraft:spawner
  block_entity_data: {
    id: "minecraft:mob_spawner",
    SpawnData: { entity: {
      id: "minecraft:blaze"
    } }
  }

THE TWO BUGS

Neither of these is your fault

They are unrelated, they have different causes, and a plugin has to handle each one separately. Most handle one.

01

Survival players place blank spawners

This one is a vanilla rule rather than a bug. Minecraft refuses to copy an item's block data onto the block unless you are op level 2, or in creative with a specific permission. A survival player places a perfectly good spawner, gets an empty one, and is told nothing about why.

No permission alone fixes it, because the bypass also demands creative mode. The only way out is to write the mob server-side after placement, which this plugin does last in the chain so the block is correct no matter what else touched it.

02

Mining a spawner returns a blank one

Every Bukkit method for asking a spawner what it spawns reads the same field on a snapshot of the block, and that field is often unset. So the method returns null, the plugin helpfully writes that null back, and null is stored as an empty entity. That empty entity is the blank spawner you end up holding.

The fix is to ask for a state backed by the live block instead of a copy. This plugin tries that first, falls back through every other method in turn, and logs which one worked.

drops nothing If every method fails it drops nothing and warns you, rather than handing out a spawner that looks fine and is not. A silent dud is worse than no item.

FEATURES

The rest of it

All of it is edited from /su admin while the server runs, and written straight back to disk.

SILK TOUCH

Who gets to collect one

Require Silk Touch and set the minimum level. Give the drop a percentage chance, then override that chance for individual mobs when a blaze spawner should be rarer than a zombie one.

FIREPROOF

It survives the lava you dropped it in

A dropped spawner ignores fire and lava, and hops out instead of sinking. The protection goes on the dropped entity rather than the item, so mined spawners still stack with shop-bought ones — and spawners this plugin never made are covered too.

0

Dupe vectors

The menus hold decoration, never real items, behind a guard that refuses clicks, drags, hotbar swaps and hopper pulls.

1

Item builder

/su give uses the same code as the mined drop, so it is a real test of that path instead of a second one that can drift.

11

Plugins checked

The startup guard names every known spawner plugin it finds, so a conflict announces itself instead of showing up as a duplicate.

EXPLOSIONS

TNT and creepers, if you want them

Off unless you turn them on, each with its own chance. Handy if you would rather people blow a farm open than stand there with a pickaxe.

PER WORLD

On where you want it

Switch the whole thing on or off per world from the menu. Per-mob permissions cover who may mine and who may place each type. Nothing here needs a text editor.

CONFLICTS

Why event priority is not enough

CMI hands its spawner straight into the player's inventory. No listener ordering can suppress that, so if its spawner module is on, one block gives you two spawners. Its own config is the only real switch.

The startup guard re-reads that file on every boot and on /su reload, checks eleven known spawner plugins by name, and prints everything registered on the break and place events.

So a conflict that turns up in six months names itself in the log, rather than appearing as a mysterious duplicate spawner.

plugins/CMI/config.yml Spawners:
  FullDisable: true

THE SCANNER

Finding the farms

/su scan groups nearby spawners into clusters and lets you jump to any of them, which is usually how you find out what people have quietly built.

It only reads chunks that are already loaded. Reaching further would mean loading or generating them, and that lags a live server. So a scan describes the world as it is in memory right now — run it while the area is occupied, which is exactly when a farm is worth looking at anyway.

COMMANDS

Five, under /su

/su give

Give someone a working spawner, built exactly like a mined one.

/su scan

Find spawner farms in the loaded chunks nearby.

/su tp

Jump to a group from the last scan.

/su admin

The live settings menu. Everything is in here.

/su reload

Reload, and run the conflict check again.

spawnersunleashed.drop

Lets a player collect a spawner at all. On by default.

spawnersunleashed.bypass.chance

Ignores the drop chance entirely.

Get SpawnersUnleashed

  1. Drop the jar into plugins/ and restart. The config writes itself.
  2. If you run CMI, set Spawners.FullDisable: true in its config.
  3. Run /su admin and set the drop chance. That is it.
